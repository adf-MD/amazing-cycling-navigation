    - **Primary-source documentation, fetched directly this session (not search-synthesis).** Three upstream sources were fetched with real `curl` (proxy unset) and read directly, resolving several points the pre-execution planning pass could only attribute to search-tool synthesis:
      - **MapLibre GL JS's own v5-to-v6 migration guide** (`https://maplibre.org/maplibre-gl-js/docs/guides/v5-to-v6-migration-guide/`, fetched directly, HTTP 200): "The dedicated CSP bundle from v5 is no longer needed. If you load MapLibre from a CDN cross-origin to your page (e.g. unpkg), the worker is constructed from a same-origin Blob URL, so your CSP needs to allow `blob:` in `worker-src`: `worker-src 'self' blob:; img-src data: blob: 'self';` If you self-host the worker file (any bundler setup), the worker URL is same-origin and `blob:` is not required: `worker-src 'self'; img-src data: blob: 'self';`" This resolves the discrepancy the pre-execution plan flagged as unconfirmed: **`img-src data: blob: 'self'` is documented as required in both the CDN and self-hosted cases alike** — it is not conditional on the worker arrangement at all, so ACN's self-hosted worker changes only the `worker-src`/`blob:` requirement, not the `img-src` one. ACN's own build matches the self-hosted case (`setWorkerUrl()` with a real Vite-built same-origin URL, confirmed above), so `worker-src 'self'` without `blob:` is the version-appropriate documented guidance — and this investigation's own browser evidence (below) confirms it actually works, not merely that it is documented.
      - **MDN's `worker-src` directive reference** (fetched directly, HTTP 200, page dated "last modified Jul 4, 2025"): "The HTTP Content-Security-Policy (CSP) worker-src directive specifies valid sources for `Worker`, `SharedWorker`, or `ServiceWorker` scripts," with fallback `child-src` → `script-src` → `default-src` if absent, and an explicit example showing `navigator.serviceWorker.register(...)` blocked by an insufficient `worker-src` — directly confirming ServiceWorker _registration_ is governed by this same directive, not a separate mechanism.
      - **MDN's "Using web workers" guide, Content Security Policy section** (fetched directly, HTTP 200): "Workers are considered to have their own execution context, distinct from the document that created them. For this reason they are, in general, not governed by the content security policy of the document (or parent worker) that created them. … To specify a content security policy for the worker, set a Content-Security-Policy response header for the request which delivered the worker script itself. The exception to this is if the worker script's origin is a globally unique identifier (for example, if its URL has a scheme of `data` or `blob`). In this case, the worker does inherit the CSP of the document or worker that created it." ACN's worker is a same-origin, regular-URL file (not `data:`/`blob:`), so the general rule applies: it does **not** inherit the document's meta CSP, and the only way to restrict its own execution would be a response header on the worker script's own request — a mechanism this static deployment does not have (see below). In practice this is low-impact here: the worker is vendored, unmodified MapLibre code, not somewhere user-controlled content ever executes.
      - **W3C's CSP Level 3 specification** (`https://www.w3.org/TR/CSP3/`, fetched directly, HTTP 200): "The `Content-Security-Policy-Report-Only` header is not supported inside a `meta` element. Neither are the `report-uri`, `frame-ancestors`, and `sandbox` directives. Authors are strongly encouraged to place `meta` elements as early in the document as possible, because policies in `meta` elements are not applied to content which precedes them." This directly confirms, from the authoritative spec text rather than search synthesis: meta-delivered CSP cannot provide Report-Only mode, `frame-ancestors`, `report-uri`, or `sandbox`, and does not govern anything preceding it in the document. The spec's own note names only those three directives; it does not separately name `report-to`, so `report-to`'s meta-delivery status is left unconfirmed by this specific passage rather than asserted either way.
