# Release 0.4.0

## Release identity

- **Version:** `0.4.0`
- **Release commit:** per this project's established convention (see
  [`docs/project/history/README.md`](../history/README.md) and every
  completed item entry in `docs/project/history/`), a document cannot
  truthfully record its own commit SHA before that commit exists. The exact
  final SHA, its GitHub Actions run, and the deployed-Pages confirmation
  are reported in the hand-off that accompanies this release rather than
  self-recorded here.
- **Previous version:** `0.3.78` (commit `8b0215c251c96afaab7317c81dcabf500a57c979`).

## What this milestone means

`0.4.0` is a deliberate, audit-driven hardening and reliability milestone
covering the accumulated work since the `0.3.x` line, closing out
[item 86's release-readiness audit](../release-readiness-audit.md) and its
follow-on items (87–93). It is **not** `1.0.0`: it makes no claim that
every backlog item, every piece of real-device field acceptance, or the
audit's own future `1.0.0` gate is complete. See
[`docs/project/current-status.md`](../current-status.md) for the full,
authoritative ledger of what remains open — this document summarises, it
does not replace it.

## User-facing highlights since the earlier 0.3 line

- **Active Riding and route/free-roam recovery and switching.** The
  App-level coordinator that arbitrates between an active route session and
  free roam, including unfinished-session switch guards, received
  dedicated characterisation coverage (item 91), materially reducing the
  audit's only Medium-severity finding without changing behaviour.
- **Camera, imagery-recovery, status-card and distance-badge polish.** A
  run of slices refined how the Riding camera behaves through stale-GPS
  and map-imagery-retry recovery, unified the status control and
  distance-badge presentation, and fixed several real, narrowly-scoped
  paint/positioning bugs found along the way.
- **Security and supply-chain hardening.** A build-only Content-Security-
  Policy is now enforced in production (item 93), based on a dedicated
  dual-engine compatibility investigation (item 90). GitHub Actions are
  pinned to immutable commit SHAs, the Playwright container is pinned by
  tag and digest, and a Dependabot policy now flags npm and Actions
  updates for review (item 88). Known dev-dependency advisories were
  remediated with a minimal, reviewed lockfile diff (item 87).
- **Broader deterministic test coverage.** The Playwright suite now runs
  three genuinely distinct projects — desktop Chromium (the full suite),
  Pixel-7-emulated `android-chrome` (Chromium-engine Android emulation),
  and a narrow `webkit-smoke` project (Safari-engine smoke coverage) —
  added as part of item 89's verification-baseline polish.
- **Diagnostics storage-health visibility.** A new storage-quota/estimate
  signal (item 92) shows the app's estimated IndexedDB usage and a
  pressure warning, confirmed live on an installed iPhone PWA.
- **Reviewed dependency remediation.** `@turf/nearest-point-on-line`,
  `@turf/helpers`, `@turf/distance`, `@turf/invariant` and `@turf/meta`
  were bumped 7.3.5 → 7.4.0 after a source-level review (see
  [Dependency decisions](#dependency-decisions) below).

## Security and privacy posture

Zero known npm audit advisories at verification, in both the full and
production-only (`--omit=dev`) audits. This is a point-in-time statement
about known, published advisories at the time this release was verified —
it is not a claim that the application is "secure" or "vulnerability-free"
in any general sense. The no-accounts, no-analytics, no-telemetry,
no-cloud-sync, local-data-only model is unchanged: imported and planned
routes, ride state, and the user's OpenRouteService key remain in this
browser's IndexedDB unless explicitly exported.

## Compatibility and data statement

- IndexedDB remains at **schema version 4** — this release introduces no
  migration.
- No GPX format or `<acn:navigation>` extension change.
- Existing saved routes, settings, and any in-progress ride state are not
  intentionally invalidated by this release.
- Service-worker updates remain user-prompted (`registerType: "prompt"`);
  nothing in this release forces an update or reload during an active
  ride.

## Verification

Full details (exact unit/E2E totals, browsers/projects exercised, local
toolchain equivalence, and final CI/deploy conclusions) are recorded in
this release's hand-off rather than duplicated here, since some of those
numbers can only be produced by the final gate run against the exact
combined tree. In summary:

- `npm audit` and `npm audit --omit=dev`: both clean at the point of
  release (0 known vulnerabilities).
- Local toolchain: this release was prepared using `corepack npm` to pin
  the exact `npm@11.16.0` required by `package.json`'s `packageManager`
  field, without modifying that field. Local Node could not be pinned to
  the exact `24.18.0` `.nvmrc` value in this environment; local results
  are therefore labelled non-equivalent toolchain and corroborated by the
  pinned-toolchain GitHub Actions run for the final commit.
- The reviewed Turf 7.4.0 lockfile update was proven via: an official
  source-level comparison (not just release notes) showing
  `@turf/nearest-point-on-line`'s own `index.ts` unchanged, and the
  `@turf/helpers`/`@turf/invariant`/`@turf/meta` changes ACN's dependency
  graph pulls in as either purely additive (new unit aliases, an unused
  `removeBbox` export) or purely cosmetic type-formatting; a byte-for-byte
  reproduction of the equivalent Dependabot PR's lockfile diff in an
  isolated worktree; full navigation-test parity before and after
  (`src/navigation/projection.test.ts` and
  `src/navigation/rideNavigationCore.test.ts`, plus the full unit suite);
  and an observational before/after production-build comparison — the
  main JS bundle changed by a small, fully explained amount (Turf's now-
  reachable unit-conversion factor table), cascading only into
  `index.html`'s script reference and the service worker's precache
  manifest, with every other build output byte-identical.

## Known limitations

See [`docs/project/current-status.md`](../current-status.md) for the full,

This release does not close every item there — notably, physical Android

## Dependency decisions

- **Turf 7.3.5 → 7.4.0 (integrated):** reviewed and integrated directly
  into this release after the source-level review summarised above. Only
  `package-lock.json` changed; no dependency ranges in `package.json` were
  altered.
- **TypeScript 6 → 7 (deferred):** the open Dependabot proposal failed
  dependency installation in CI at both required jobs. The repository's
  current `typescript-eslint@8.68.0` documents a peer contract of
  `typescript >=4.8.4 <6.1.0`, incompatible with TypeScript 7. TypeScript 7
  is deferred — not rejected — until the repository's lint/compiler
  toolchain officially supports it and the migration can be reviewed as
  its own dedicated slice, not folded into release preparation. A scoped
  Dependabot ignore (semver-major only, so a genuine security update can
  still surface) records this.

## Update verification

landed.
